# Аудит легаси-сайта dachpedigrees.com

**Дата обследования:** 21 августа 2026
**Источник:** живой сайт `http://www.dachpedigrees.com`, закрыт HTTP-авторизацией
(учётные данные — у владельцев проекта, в репозитории не хранятся,
передаются скрипту через `LEGACY_AUTH`)
**Метод:** обход публичных страниц curl'ом, разбор HTML. Дампа БД на момент
аудита не было, поэтому всё ниже — наблюдения по отрендеренным страницам.

Что это даёт: имена CCK-полей видны в классах разметки (`field-field-*`),
справочники — в выпадающих списках формы поиска. Чего это **не** даёт:
полей, пустых у всех осмотренных собак; точных типов и кратности полей;
настоящих объёмов. Всё помеченное «уточнить по дампу» проверить заново.

## 1. Карта сайта

```
/                         почти пустая: «Welcome!» + список 10 последних собак
/search-dog               поиск: имя, титулы, порода, клеймо/чип, заводчик, страна
/node/<nid>               карточка собаки
/dog/<slug>-nid/<nid>     она же по псевдониму URL
/node/<nid>/image_gallery галерея фото
/dogs/virtual             виртуальная вязка
/dogs/showvirtual         её результат (Sire / Dam)
/dogs/addlitter           добавить помёт          — Access denied
/node/add/dog             добавить собаку         — Access denied
/node/add/ownerbreeder    добавить заводчика      — Access denied
/content/welcome  /contact  /tracker  /user/register  /user/password
```

Формы редактирования закрыты: выданные учётные данные — это HTTP-авторизация
всего сайта, а не учётная запись Drupal. Права на ноды остались анонимные.

**Счётчик в шапке: 50 659 собак.**

Псевдоним URL строится как `/dog/<транслит-клички>-nid/<id ноды>`. Числовая
часть — идентификатор ноды, поэтому редиректы со старых адресов делаются
механически по `legacy_id`, разбирать слаг не нужно.

### Ловушки в именах

- `field_date_burn` — опечатка, `burn` вместо `born`. Поле смерти при этом
  называется `field_death_date`, порядок слов другой. Обращаться дословно.
- Пол отдаётся картинкой `images/famale.gif` — опечатка и здесь.
  Само значение поля со страницы не видно, **уточнить по дампу**.
- `field_nid_dog` — **отдельное текстовое поле, а не идентификатор ноды.**
  На осмотренных собаках совпадает с id (`484554` = `node-484554`),
  но полагаться на это нельзя.

## 3. Справочники

Порода и титулы — **не свободный текст**, а списки: видно по форме поиска,

`docs/legacy/breed-map.json` — готовая таблица соответствий.
Три размера × три типа шерсти, наше разделение на `size` / `coat`

| Легаси | size | coat |

| `Kaninchen- dachshund (teckel) kurzhaar` | rabbit | smooth |

Обратить внимание на разный пробел: `Kaninchen- dachshund` против

### Титулы: 121 значение

`docs/legacy/titles.txt`. Хранятся одной строкой через запятую:
`INTCH,EUW,BLRCH,FINCH,RKFCH,ROMCH,RUSCH,RUSJCH`. Страны в значении нет —
она зашита в саму аббревиатуру (`RKFCH` — Россия, `BLRCH` — Беларусь).
Титулов на собаку бывает под тридцать.

Полей титулов **три**, не одно: `field_titles` (выставочные),
`field_other_titles` (прочие, например `CW`), `field_p_titles`
(полевые испытания, например `FT-FOX`).

## 4. Что придётся распутывать в ETL

1. **Заводчик и владелец хранятся дважды.** `field_breeder1` / `field_owner1` —
   ссылка на ноду типа `ownerbreeder`; `field_breeder_not_db` /
   `field_owner_not_db` — тот же человек свободным текстом, «когда его нет
   в базе». Сливать в одну сущность с дедупликацией. Формат строки:
   `Victoria IVANOVA & Vasiliy IVANOV ( MAGIK RAINBOW Russian Federation )` —
   то есть внутри одного значения сидят имена людей, название питомника
   и страна. Структуру ноды `ownerbreeder` посмотреть **по дампу**.
2. **Клеймо и микрочип — одно поле** `field_tatoo` с подписью
   «Tatoo/Microchip». В нашей схеме это разные сущности. Разделять
   эвристикой: микрочип — 15 цифр, клеймо — буквы с цифрами.
3. **Окрас — свободный текст и вразнобой:** `black&tan`, `brown&tan`,
   `Chocolate & Tan Dapple`, `red`, `Creamy Red`. Регистр и пробелы вокруг `&`
   не нормализованы. Внутри окраса прячется генетика: **`Dapple` — это локус M**,
   то есть часть данных для модуля здоровья уже лежит в базе, просто
   в текстовом поле.
4. **Регистрационный номер один** (`field_reg_number`, `RKF 1588613`),
   у нас запланировано несколько на собаку. Кратность **уточнить по дампу**.

## 5. Качество данных

**В поле клички лежат рабочие пометки администратора.** Поиск по вхождению
в название:

| Подстрока | Порядок записей |
|---|---|
| `wrong` | 800–900 |
| `double` | ~100–200 |
| `foto` | 86 |
| `discard` | 13 |
| `test` | ~40 |

Это записи с кличками `wrong foto`, `double foto`, `discarderd file`,
`Wrong  foto` (двойной пробел) и подобными. Плюс спам-ноды с текстами вроде
`Lebron james 30 factors desire 10 80-69 South america...` и
`Dad to save lots of critically unwell boy insisted upon Cross bloodstream...`.

Итого около тысячи мусорных нод на 50 659 — примерно **2%**. В ETL отсеивать,
а не переносить. Цифры сняты с пагинатора выдачи, точные считать по дампу.

**Заполненность паспортной части низкая** — см. таблицу в разделе 2.
Дата рождения есть у 9 собак из 12, регистрационный номер у 6, заводчик
у 3–4, клеймо у 1. Выборка мала, но порядок понятен: карточка обязана
выглядеть нормально, когда заполнено три поля из двадцати.

## 6. Кодировки

Страница объявляет `charset=utf-8`, а внутри лежит **CP1251**. Проверено:
байты `\xcd\xee\xe2\xee\xf1\xf2\xe8` декодируются как «Новости» в cp1251
и ломают разбор как UTF-8. Смешаны в пределах одного документа.

Дамп чинить придётся побайтово, по колонкам: сначала пробовать UTF-8,
на ошибке откатываться к CP1251. Рабочая реализация — в `scripts/legacy_fetch.py`,
функция `fix()`.

Клички бывают кириллицей (`ДЛЯ ТЕБЯ ВЕЧНАЯ ЗАГАДКА ИЗ ГОРОДА ТАКС`)
и с диакритикой (`Ossa Kamenný potok`). Сортировка и поиск должны
это переживать — отсюда `unaccent` в Postgres.

## 7. Безопасность: скрытая ссылка в шаблоне

В подвале **каждой** страницы зашито:

```html
<a href="http://pksport.ru"><span style="color: #fefefe;">Новости спорта
в Приморском крае. Спорт во Владивостоке, Уссурийске, Находке...</span></a>
```

Белым по белому фону. Это либо след взлома, либо торговля ссылками.
К поисковым санкциям отношение имеет прямое — и может объяснять,
почему трафик низкий.

**Действия:** в новый проект не переносить (контент темы не мигрируем),
но при ETL проверить пользовательские тексты на такой же мусор —
скрытые ссылки могли попасть и в тела нод.

## 8. Что уже есть у легаси и чего нельзя потерять

- **Виртуальная вязка** (`/dogs/virtual`) — то, что мы называем пробной.
  Работает, ей пользуются.
- **Подсветка повторяющихся предков** в родословной. CSS-классы:
  `maletwice`, `malethree`, `malefour`, `femaletwise` (опечатка в оригинале),
  `femalethree`, `femalefour`. Ровно шесть ступеней — оттенок кодирует пол,
  насыщенность число повторов. Наша шкала в `frontend/src/styles/tokens.css`
  повторяет эту семантику. Родословная в легаси на **4 поколения**.
- **Домашняя кличка** (`field_home_name`) — показывается в скобках рядом
  с официальной, заводчики ей пользуются. В макете нового интерфейса её нет,
  добавить.
- **Галерея фото** на отдельной странице `/node/<nid>/image_gallery`.

## 9. Открытые вопросы к дампу

- значения `field_gender` (на странице видна только картинка);
- кратность `field_reg_number` — одно значение или несколько;
- структура ноды `ownerbreeder`: отдельные ли поля под питомник и страну
  (в форме поиска фильтр «By breeder country» есть, значит скорее да);
- существует ли отдельное поле микрочипа помимо `field_tatoo`;
- устройство помётов: `/dogs/addlitter` закрыт, сущность не осмотрена;
- точные объёмы мусора;
- есть ли поля, пустые у всех 12 осмотренных собак.
